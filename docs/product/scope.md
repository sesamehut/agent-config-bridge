# 产品范围

## 要解决的问题

同一个项目同时使用 Claude Code 和 Codex 时，项目级配置通常被拆成两套：
Claude Code 读取 `CLAUDE.md`、`.claude/rules/` 和技能目录，Codex 读取
`AGENTS.md`、`.agents/skills/` 技能目录和 `.codex/hooks.json`。直接复制一份可以
应急，但后续维护不可靠：一侧修改后另一侧容易遗漏，名字相近的工具能力也可能并不
等价。

Agent Config Bridge 的目标是让用户在工具之间快速切换而配置只维护一份：项目中的
Claude 形态配置树被声明为唯一源，其余 host 可见配置由它投射生成。用户在任一工具
的会话里表达配置意图，改动都会落进源树并同步到各投射面；直接改在投射面上的内容
（哪怕改的是 `AGENTS.md` 里来自规则分片的段落）会被自动采纳回源树对应位置再
重投射。`CLAUDE.md` 与 `AGENTS.md` 都不需要人工双份维护。

## 立场：工具等权重

本项目不预设主次工具。使用各工具的用户权重相同，产品目标就是降低切换成本。源树
采用 Claude 形态布局，是因为它在同步范围的语义（技能、规则 / 指令、钩子）上是
两个工具配置结构的超集、且被一个 host 原生消费——这是容器 schema 的工程选择，
不是"Claude 优先"。体验必须对称：

- 从任一工具编辑配置，效果都到达两个工具。
- 源树每个语义单元在对方 host 以可达的最高保真度生效；缺机制只降档，不丢弃。
- Codex 起点的项目与 Claude 起点的项目获得同等的引导路径。

## 面向用户

- 在同一个仓库里交替使用 Claude Code 与 Codex 的个人开发者。
- 希望把项目级智能体约定维护成一份、供多工具使用的仓库维护者。
- 已有单侧配置（Claude 树或 `AGENTS.md`）、希望迁到共用约定的用户——两种起点
  同等支持。

## MVP 范围

MVP 只处理项目级配置，先覆盖三类内容：

- **技能**：以技能目录为单位，包括 `SKILL.md`、脚本、资源和引用文件；母本复制。
- **规则 / 指令**：入口文件与规则分片，含 path-scoped 规则的降级投射。
- **钩子**：按意图建模（触发点、目的、命令、环境要求、失败策略），向两侧的
  原生 hooks 配置面投射；超出目标侧 hooks 能力面的意图降级为常驻指令，并在
  同步计划中如实标注档位。

这个范围刻意保持小。技能最适合先验证快路径与投射模型；规则和钩子更容易遇到工具
语义差异，需要在投射和采纳流程稳定后逐步展开。

## MVP 之外

MCP 服务器、智能体 / 子智能体、全局用户配置、权限模型（含 Claude 权限规则与
Codex 审批规则的映射）、模型选择和第三方 IDE 规则不在 MVP 内。Codex 审批 / 沙盒
规则声明为 Codex 所有、不同步。

分发目标是插件自带 skill 与工具映射知识，再配一个很薄的包装脚本。用户安装插件
后，即可在对应工具中调用这些能力。

## 产品约束

1. **单一源树，双向传播**。共享语义的唯一真相在源树；改动可以发生在任何一面，
   落在投射面上的改动经反向采纳回到源树，再重投射。投射面不反向拥有内容。
2. **完备投射**。源树每个语义单元到达每个 host，取可达最高保真档；`unsupported`
   只能来自显式声明，不允许静默丢弃。
3. **传播自动、决策必问**。无歧义的正向投射与反向采纳自动执行，同步计划随写入
   作为报告产出；冲突、收编既有人工内容和扩大自动执行面必须先取得用户确认。
4. **冲突不自动合并**。源树与投射面同时携带不同新意图时报告 `conflict`，由用户
   选择；[仲裁](../architecture/overview.md)在冲突单元上只提供证据与建议，
   不代替用户合并。
5. **按语义映射**。提示词指令、执行许可、自动化配置分属不同语义，只同步语义可
   解释的部分。
6. **写入可追溯**。投射与采纳都通过 git 留痕：`git diff` 展示精确变更，历史提供
   仲裁证据，必要时可以回滚；采纳需要说明为什么可以进入源树。

## 成功标准

MVP 达标的检验是切换测试：

- 用户在任一工具会话中新增或修改技能、规则或钩子意图，另一个工具无须额外操作即
  可看到对应效果，或被明确告知降档 / 不支持及其原因。
- 用户手改投射面后，[哨兵](../architecture/overview.md)能发现漂移，无歧义的
  改动被自动采纳回源并重投射，冲突被如实报告并等待用户选择。
- 每个语义单元的保真档位在同步计划中可解释。
