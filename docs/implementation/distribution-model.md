# 分发模型

## 仓库角色

本仓库采用单仓库模式：上游开发态内容（skill 源、工具映射知识、薄包装脚本源、文档、
测试）和可安装插件产物位于同一个仓库。分发形态由未来的内部 `plugin/` 子目录承载。

Bridge 的主要产物是 skill 和知识库，代码只承担入口和辅助检查职责。仓库内部按角色分层：

- `skills/`：skill 源，面向目标工具中智能体的 skill 内容，markdown 为主；可含
  必要的宿主元数据、参考资料和过窄门的只读机械辅助脚本，入库。
- `templates/`：面向目标项目安装的约定模板等写入素材，与只读 skill 指令分离，
  入库；只有路线图开放相应写路径后才会安装。
- `knowledge/`：工具映射知识，自然语言知识库，带采集日期，入库。
- `fixtures/`：验证用夹具项目，携带已知状态与期望报告，供哨兵等 skill 对照
  校验，入库。
- `src/`：薄包装脚本源（若包装脚本使用 TypeScript），入库。
- `dist/`：包装脚本的构建中间产物，不入库（写进 `.gitignore`）。
- `plugin/`：可安装插件产物，作为**入库的边界产物**提交，供市场按“仓库 + 子目录路径”
  安装；skill 与知识从上游拷入，薄包装脚本从 `dist/` 拷入。

`plugin/` 虽然入库，但仍按生成物管理。要改变行为，应修改上游 skill、知识或包装脚本后
重新组装，不直接手工编辑产物目录。

## 形态：skill 为主，包装为辅

分发主体是 skill 和工具映射知识。它们本身是文本，不需要编译成可执行文件。只有当目标工具
入口需要稳定调用点时，才提供薄包装脚本。用户机必须有 git；M1 哨兵的只读机械辅助脚本
要求 Python 3.9+；Node.js 仅在后续包装脚本需要时作为运行时。git 以外的前置由 skill
在开工前做环境预检，缺失时向用户报告缺什么、怎么装，而不是静默降级。

这种分发形态带来几个直接收益：

- 用户安装插件后即可获得快路径 / 哨兵 / 仲裁 skill，具体流程由目标工具中的智能体执行，git 提供变更依据。
- Claude Code 插件与 Codex 插件可以分别适配各自入口。
- 薄包装脚本便于做产物允许清单、密钥扫描、版本锁定和离线 doctor。

## Claude Code 入口

官方插件参考确认（核对日期 2026-06-17）：`${CLAUDE_PLUGIN_ROOT}` 会被 Claude Code 在
**加载技能内容时就地替换**成插件安装目录的绝对路径；智能体 Bash 子进程中不会因此出现
同名环境变量。所以技能正文可以直接写依赖它的命令或文件引用，智能体读到时路径已经是
绝对路径：

```text
node "${CLAUDE_PLUGIN_ROOT}/scripts/bridge.mjs" status
```

这里的 `bridge.mjs` 是薄包装脚本。投射 / 仲裁判断仍由 skill 正文和工具映射知识完成。
定位自带文件有两个锚点：`${CLAUDE_PLUGIN_ROOT}` 指插件根目录，`${CLAUDE_SKILL_DIR}` 指
技能自身子目录（官方推荐用于“随技能打包”的文件，例如工具映射知识片段）。

持久状态使用 `${CLAUDE_PLUGIN_DATA}`（`~/.claude/plugins/data/{id}/`，跨更新保留）。
实现时应避免依赖某次安装的绝对路径；插件更新后路径会变，旧路径会沿用到
`/reload-plugins`。

## Codex 入口

Codex 侧入口以技能本地包装脚本为默认设计。包装脚本放在技能自己的 `scripts/` 目录里：

- 插件清单指向 `skills` 目录。
- Codex 技能自带轻量包装脚本。
- 包装脚本从自身位置回溯到插件产物里的薄包装脚本与工具映射知识。
- 技能文档只要求目标工具中的智能体调用这个技能本地包装脚本。

这个设计只依赖稳定文件布局。Codex 已为插件 hook 进程注入 `PLUGIN_ROOT` /
`PLUGIN_DATA`（并为兼容注入 `CLAUDE_PLUGIN_ROOT` / `CLAUDE_PLUGIN_DATA`），hook
命令可直接依赖；但技能正文没有文档化的插件根目录就地替换机制，Codex 技能入口因此
以技能本地包装脚本为默认设计。若 Codex 未来为技能正文提供等价机制，可以把包装
脚本继续收薄，同时保持面向目标工具中智能体的工作流不变。

## 插件产物

未来产物至少需要包含：

- 目标工具清单：Claude Code 与 Codex 各自需要的插件元数据。
- 技能：触发 Bridge 投射 / 哨兵 / 仲裁工作流的目标工具 skill。
- 工具映射知识：Claude Code / Codex 语义差异的自然语言知识，带采集日期。
- 薄包装脚本：交付 skill、定位自带文件、执行 doctor 的可选 `bridge.mjs`。
- README / 智能体指引：说明前置要求（git，必要时 Node）、安装方式、doctor、安全边界，
  以及 `plugin/` 产物目录的生成物属性。

产物生成应该使用允许清单。发布物只包含经过审计的文件，避免把本地环境变量、密钥、调试
输出和其他开发期内容带入插件。

## 版本策略

发布时需要让这些版本一致：

- 包版本 / 源码版本。
- 薄包装脚本 `--version`（若提供）。
- 插件清单版本。
- 市场条目版本。
- 生成产物 README 中展示的版本。

版本一致性应该成为发布前门禁。早期机制可以由发布脚本完成：版本不一致时直接失败，避免
发布后再人工排查。

## 市场发布

市场集成放在插件产物可安装、doctor 可用、版本策略稳定之后。到时再决定是否更新类似
`sesamehut/plugins-marketplace` 的市场条目。

在此之前，仓库保持开发状态，市场条目随发布阶段一起进入计划。
