# 路线图

## 当前状态

本仓库现在处于设计与项目约定阶段。这个阶段只放文档、规则和规划文件；skill、工具映射
知识、薄包装脚本、插件清单和制品产物从 M1 起的实现阶段开始引入。

路线图按风险递增推进：先确定规范源结构和 skill 工作流，再做只读同步计划；随后从技能
这种低风险配置面开始落盘，最后处理规则、钩子和分发。

## M1：规范结构与 skill 投射骨架（只读）

M1 是只读阶段。目标是确定规范源形状和 skill 工作流，让后续落盘建立在清楚的输入和分类
规则上。

要完成：

- 选定规范源格式（markdown + frontmatter 加目录约定）。
- 定义技能 / 规则 / 钩子的条目标识与目标策略。
- 起草 Bridge skill 工作流骨架：触发 -> 用 git 读变更 -> 对照规范源 -> 出同步计划。
- 起草工具映射知识的初始结构（带采集日期）。

完成标准：

- 能扫描一个示例项目，基于 `git diff` / `git status` 报告规范源、Claude 配置文件、
  Codex 配置文件的差异与意图分类。
- 能区分受管（带受管区块）、未受管、已变化、`unsupported`。
- 没有落盘能力；所有结果只停留在同步计划。

## M2：技能投射与对账

技能是第一块落盘配置面。它的目录结构相对清楚，Claude Code 和 Codex 都能消费
`SKILL.md`，适合用来验证投射、受管区块和 git 漂移检测。

要完成：

- 实现 skill 投射规范技能到 Claude / Codex 项目技能。
- 用受管区块标记加落盘前 diff 自检，保证输出稳定。
- 实现 reconcile skill：基于 git 历史基线检测漂移，给出合并建议。

完成标准：

- 用户只维护规范技能，Claude Code 与 Codex 都能看到投射结果。
- 未带受管标记、看起来由用户手写的目标工具技能副本不被覆盖，skill 停下来问采纳还是替换。
- 规范源与目标工具配置文件相对上次同步态同时变化时报告 `conflict`。

## M3：规则 / 指令投射

规则在技能之后处理。原因是 `CLAUDE.md`、`.claude/rules/` 和 `AGENTS.md` 都是面向智能体
的指令，而 Codex 命令审批 / 沙盒规则属于执行许可和沙盒控制，不能直接按文件名等价处理。

要完成：

- 设计规范规则的组合模型。
- 用受管区块在 `CLAUDE.md` 与 `AGENTS.md` 中让人工内容与投射内容共存。
- 区分提示词指令与 Codex 命令审批 / 沙盒类规则。

完成标准：

- 共用规则只维护一份。
- 工具特化附录可以显式存在。
- 语义不同的配置以 `partial` / `unsupported` 呈现。

## M4：钩子映射知识

钩子放在更后面，因为风险主要来自执行语义。不同工具的触发时机、环境变量、权限和失败
处理都可能不同。

要完成：

- 建立钩子意图模型。
- 在工具映射知识里写清楚每类钩子意图在 Claude / Codex 上能表达到什么程度。
- 让 skill 在同步计划里给出每个钩子的 `full` / `partial` / `unsupported` 状态。

完成标准：

- 高副作用钩子默认要求显式启用。
- `unsupported` 以独立状态呈现。
- 同步计划能解释每个钩子在两个工具上的状态。

## M5：插件打包（skill 加薄包装）

等同步模型稳定后，再做插件产物。这样可以先验证入口、目录和写入策略，再固定发布形态。

要完成：

- 把 skill、工具映射知识和薄包装脚本组装成 Claude / Codex 插件。
- Claude 技能使用 `CLAUDE_PLUGIN_ROOT` 定位自带文件与薄包装脚本。
- Codex 技能使用技能本地包装脚本。
- 在单仓库内生成插件产物到入库的 `plugin/` 边界目录。

完成标准：

- 用户安装插件后获得配套 skill 与工具映射知识。
- 产物由允许清单生成，并经过密钥扫描。
- `plugin/` 入库但明确声明生成物属性：由上游组装，不手工编辑。

## M6：稳定化

最后阶段处理跨平台、可靠性和发布。这里维持既定范围，重点是把已经支持的配置面做稳。

要完成：

- 补齐跨平台路径、换行；确保 git 操作在不同环境下行为稳定。
- 强化 `conflict` / 对账的 skill 行为与示例。
- 建立发布前验证命令和 CI 门禁（以文本 / 链接校验和版本一致性为主）。

完成标准：

- 示例项目覆盖技能 / 规则 / 钩子三类 MVP 配置面。
- 投射与对账的 skill 行为稳定，落盘前确认与收尾自检可靠。
- 发布流程能复现生成产物。
